# FELAG — Product Roadmap

## Product vision

FELAG helps travellers find people from their home who will be
in the same destination at the same time.

Core proposition:

> You tell FELAG where you're going and when.
> FELAG tells you who from your home will be there.

The core differentiator is the matching between:
- where a user comes from
- where they are travelling
- when they are travelling

# Phase 3 — FELAG Matching

Goal: detect when users from related origins are travelling
to the same destination at overlapping times.

## Matching

- [ ] Destination normalization
- [ ] Date overlap detection
- [ ] Origin matching
- [ ] Country-level matching
- [ ] Region-level matching
- [ ] Town-level matching
- [ ] Match ranking
- [ ] Match explanation

Example:

User A
Barcelona → Tokyo
10–20 October

User B
Barcelona → Tokyo
14–18 October

Result:

> 1 FELAGI from Barcelona will be in Tokyo
> while you're there.

## Notifications

- [ ] Match notification
- [ ] Notification preferences
- [ ] Deep link to match

Definition of done:
- Two users with compatible origins, destination and overlapping
  dates are matched.
- The match is visible to the user.
- The user receives a notification.

# Agent execution rules

The orchestrator is responsible for deciding which agent works next.

Agents must NOT implement future phases unless explicitly requested
by the orchestrator.

For each task:

1. Read ROADMAP.md
2. Read relevant product and architecture documentation
3. Identify dependencies
4. Implement the smallest required change
5. Run relevant tests
6. Report what was changed
7. Report blockers
8. Do not modify unrelated domains

The orchestrator must maintain the roadmap status.

A phase is complete only when:
- its acceptance criteria are met
- QA has validated it
- required infrastructure is available
- no blocking dependency remains
